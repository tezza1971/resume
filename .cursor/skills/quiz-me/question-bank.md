# Quiz question bank

Ask **1–2 questions per turn**. Capture answers; never invent metrics. If a metric is missing, use the follow-ups before drafting the bullet.

## 1. Target role

1. What job title / job family are you targeting? (e.g. Staff Platform Engineer, Engineering Manager)
2. Seniority and domain focus? (IC vs lead; cloud, frontend, data, security, etc.)

## 2. Contact and links

1. Full name, email, phone, city/region (country if useful)?
2. LinkedIn, GitHub, portfolio/site URLs to include? Any to omit?

## 3. Career arc

1. Rough years of relevant experience and primary domains?
2. Work constraints for the structured JSON only if you want them public: remote preference, open-to-work, visa/work authorization notes?

## 4. Experience (repeat per role, newest first)

For each role, gather in order (may span multiple turns):

1. Company, title, location (city/remote), start and end as `Month YYYY` (use `Present` if current)?
2. Stack and systems you actually used in this role?
3. List 2–5 concrete outcomes (what changed for users, revenue, reliability, cost, or speed)?

**Metric follow-ups** (ask when an outcome lacks numbers):

- By how much? (% , absolute, time saved, $ , error rate, latency p50/p95)
- Over what scope? (users, services, team size, regions, traffic)
- Before vs after, or vs a baseline?
- If unknown: say so — draft a qualitative bullet; do **not** fabricate a number

## 5. Skills

1. Grouped skills for the target role: Languages, Frameworks, Cloud/Infra, Tools, Certifications (aim ~12–20 specific items)?
2. Any must-have JD keywords to weave into bullets/summary *only if true*?

## 6. Education and certifications

1. Degrees: school, credential, field, dates (or year)?
2. Certifications worth listing (name, issuer, year)?

## 7. Projects (optional)

1. Notable projects outside employment: name, one-line problem, your role, stack, outcome/link?

## 8. Summary inputs

1. In one sentence: who you are for this target role?
2. One recent achievement that should appear in the summary (with a real metric if you have one)?

## Completion gate

Enough to plan when you have: target role, contact, ≥1 experience role with dates + outcomes, and a skills list. Then create a plan for `resume.md` + `resume.json` — do not write files until the user confirms.
